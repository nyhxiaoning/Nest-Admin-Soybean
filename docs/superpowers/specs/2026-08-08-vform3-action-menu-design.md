# VForm 3 表单操作下拉菜单设计

## 背景

VForm 3.0.10 默认将清空、预览、导入 JSON、导出 JSON、导出代码和生成 SFC 横向排列在右侧工具栏中。即使显式启用按钮并扩大工具栏，在嵌入管理后台的窄内容区内，官方工具栏仍可能被横向滚动区域推到首屏之外，造成“功能存在但不可见”。

## 目标

- 将六项横排操作收拢为一个始终可识别的 `表单操作` 下拉按钮。
- 菜单纵向展示以下功能：
  - 清空
  - 预览
  - 导入 JSON
  - 导出 JSON
  - 导出代码
  - 生成 SFC
- 每个菜单项继续调用 VForm 3.0.10 的官方公开方法，复用官方弹窗、导入导出和代码生成逻辑。
- 保留现有 `1500 × 800px` 防挤压边界、双向滚动及 SVG 图标兼容修复。

## 方案

### VForm 配置

继续通过 `designerConfig` 配置设计器，但将六个官方横排按钮开关设置为 `false`，避免重复展示和占用宽度。将 `toolbarMinWidth` 和 `toolbarMaxWidth` 都设置为 `140px`，仅为单个菜单入口预留空间。

### 菜单插槽

使用 `VFormDesigner` 向官方 `ToolbarPanel` 透传的工具栏插槽，在原右侧工具栏内部渲染一个 Element Plus 下拉菜单：

- 触发按钮文案为 `表单操作`。
- 下拉菜单使用点击触发，避免悬停误打开。
- 六个菜单项使用稳定的命令值：`clearDesigner`、`previewForm`、`importJson`、`exportJson`、`exportCode`、`generateSFC`。
- `清空` 放在菜单末尾，前面添加分隔线，并使用危险色，降低误操作风险。

### 方法分发

为 `designerRef` 声明仅包含上述六个公开方法的本地接口。菜单的 `command` 事件交给单一分发函数处理：只接受六个命令联合类型，从 `designerRef` 获取对应方法并调用。若设计器尚未挂载，函数安全返回，不抛出异常。

该方案不重新实现 VForm 的对话框和业务逻辑，也不依赖官方横排按钮是否处于可视区域。

## 交互流程

1. 用户点击 `表单操作`。
2. Element Plus 展示纵向菜单。
3. 用户选择一个菜单项。
4. 页面将命令映射到 `designerRef` 的同名公开方法。
5. VForm 打开对应官方弹窗或执行官方清空流程。

## 测试与验收

- 组件测试验证原生六按钮开关均为 `false`，工具栏只保留菜单所需宽度。
- 组件测试验证 `表单操作` 入口和六个菜单项均存在。
- 对六个命令分别触发分发函数，验证对应 VForm 公开方法各调用一次。
- 真实挂载 VForm，确认页面不再依赖六个横排按钮文字。
- 运行目标 Vitest、前端 ESLint 和 Vite 生产构建。
- 手工打开 `/tool/build`，在窄内容区确认 `表单操作` 入口可见，并逐项打开五个非破坏性弹窗；清空仅验证命令可触发，不确认删除已有表单内容。

## 非目标

- 不修改 `vform3-builds` 源码。
- 不自建预览、JSON 或代码生成弹窗。
- 不改变 VForm 的 JSON 格式和生成代码内容。
- 不改变管理后台其他页面的菜单与滚动行为。
