# VForm 3 设计器双向滚动优化设计

## 背景

`/tool/build` 当前将 VForm 3 设计器放入占满路由内容区的容器，并使用 `overflow: hidden`。VForm 设计器包含左右侧栏和中间画布；当后台内容区宽度或高度不足时，内部 Flex 布局会压缩面板和组件，且超出内容无法通过滚动访问。

## 目标

- 保持 VForm 3 桌面设计器原始布局和组件比例，不通过缩放适配窄窗口。
- 设计器可用区域不足 `1200 × 800px` 时，在路由内容区出现水平和垂直滚动条。
- 可用区域大于最小尺寸时，设计器继续铺满路由内容区。
- 不修改 `vform3-builds` 依赖源码，不影响拖拽、配置和 JSON 等现有功能。

## 方案

滚动职责由 `/tool/build` 页面外层承担：

1. `.vform-designer-page` 保持路由内容区的 `width: 100%`、`height: 100%` 和 `min-height: 0`，将 `overflow` 从隐藏改为自动。
2. VForm 根节点 `.el-container.full-height` 设置 `min-width: 1200px`、`min-height: 800px`，同时保留 `width: 100%`、`height: 100%`。
3. 当内容区小于最小尺寸时，根节点产生溢出，由外层在底部和右侧分别提供滚动条；空间足够时不会产生无意义滚动。
4. 样式继续使用 Vue scoped CSS 的 `:deep()` 定位第三方根节点，避免污染其他页面。

选择该方案是因为它只约束第三方组件的整体边界，不依赖 VForm 内部左右栏或画布的实现细节。后续升级 VForm 时，比覆盖多个内部面板样式更稳定。

## 测试与验收

- 组件测试验证页面外层具有可识别的滚动容器类，VForm 仍为直接渲染。
- 静态样式断言验证外层使用 `overflow: auto`，VForm 根节点具备 `1200px` 和 `800px` 的最小尺寸。
- 执行目标组件测试、ESLint 和 Vite 生产构建。
- 手工缩小浏览器内容区，确认底部出现水平滚动条、右侧出现垂直滚动条，左右面板和中间画布不被继续压缩。

## 非目标

- 不实现移动端或响应式精简版设计器。
- 不修改管理后台的全局滚动策略。
- 不调整 VForm 内部侧栏、工具栏和画布的固定尺寸。
- 不改变表单数据保存、导入或导出逻辑。
